# uTools 进制转换插件 — 设计分析与实施规划

**状态**：设计分析（未动代码）
**目标**：做一个自己天天愿意用的进制转换插件 —— 核心不是"能转换"，而是**在任何写代码/看日志的上下文里，用最少的动作拿到结果**。
**技术底座**：uTools 7.8.0（已装）+ Vue3 + Vite6（项目现为官方模板）
**依据**：uTools 官方文档（plugin.json / preload / events / window / system / copy / input / db / 目录结构 / 调试）+ 本地 `node_modules/utools-api-types/utools.api.d.ts` 类型定义

---

## 一、结论先行：什么决定这个插件"好用"

uTools 插件有三种触达方式，好用程度差别巨大：

| 入口 | 用户动作 | 适合 |
|---|---|---|
| 功能指令（打开界面） | 热键 → 输入"进制转换" → 回车 → 再输入 | 需要反复试算、看多个视图 |
| **匹配指令（regex）** | **选中数字 → 热键带入 → 回车 → 结果自动粘贴回原窗口** | **看代码时想知道某个常量的值** |
| onMainPush（搜索框推送） | 在主搜索框输入即看到候选结果 | 半自动、零切换 |

**结论：这个插件的价值 80% 在"匹配指令 + 回车即粘贴回原窗口"，而不是那个转换界面。**
界面是"需要细看时"的后备入口。设计重心应该按这个比例分配。

典型的黄金路径（也是选择这个插件而不是网页版计算器的唯一理由）：

```
IDE 里选中 0x7FFFFFFF
  → 按 uTools 热键（选中内容自动带入主搜索框）
  → 候选列表出现「十六进制转换  →  2147483647」
  → 回车
  → 2147483647 直接粘贴替换掉原选中内容，光标还在 IDE 里
```

全程不打开插件、不切换窗口、不手写复制粘贴。这条路径必须先跑通。

## 二、场景盘点（决定功能取舍）

结合嵌入式 / Qt / STM32 的实际工作：

| # | 场景 | 频率 | 备注 |
|---|---|---|---|
| 1 | 看代码里的 `0x...` 想知道十进制 | 高 | 匹配指令覆盖 |
| 2 | 寄存器位操作：`0x0F00` 置了哪些位 | 高 | **需要二进制视图 + 位图** |
| 3 | 二进制反推十六进制（配置寄存器） | 高 | `0b...` 匹配指令 |
| 4 | 字节序：`0x12345678` → `12 34 56 78` / `78 56 34 12` | 高 | 通信调试刚需 |
| 5 | 有符号解释：`0xFFFFFFFF` = 32 位有符号 `-1` | 高 | **必须做，纯 JavaScript 直觉会错** |
| 6 | IEEE754：`0x3F800000` ↔ `1.0f` | 中 | Modbus/串口浮点 |
| 7 | 位宽补零：`0x0F` → `0000 1111` | 高 | 嵌入式刚需 |
| 8 | 大数：超 64 位十六进制 | 低 | BigInt 免费拿到 |
| 9 | 颜色 `#FF5733` ↔ RGB | 低 | 属于"编码转换"，另说 |
| 10 | ASCII/Unicode/时间戳 | 中 | 属于"编码转换"，**不建议塞进这个插件** |

**范围纪律**：只做"进制"。颜色、编码、时间戳、Base64 全都不是进制转换，硬塞进来会让插件变成大杂烩，也让 `plugin.json` 的匹配指令互相打架。要就单开插件。

## 三、功能分层

### v1 —— 最小可用闭环（必做）
1. **界面**：单输入框 + 自动识别，2/8/10/16 四行实时联动，点击即复制
2. **匹配指令**：`0x` / `0b` / `0o` 前缀 → 搜索面板直达 → 回车粘贴回原窗口（+ 一个"复制"选项）
3. **数值处理**：BigInt（任意长度）、负数、下划线/空格/全角容错
4. **界面细节**：深浅色跟随系统、高度自适应、非法输入不崩只提示

### v1.5 —— 让它是"我的"工具（强烈建议，按嵌入式需求排优先级）
5. **位宽视图**：8/16/32/64 × 有符号/无符号（`0xFFFFFFFF` → `-1` / `4294967295`）
6. **补零分组显示**：二进制按 4 位/8 位分组（`0000 1111`），十六进制按 2 位分组
7. **字节序**：大端/小端字节序列，支持空格/逗号分隔
8. **位图**：32 位点阵，直观看出哪些 bit 置位
9. **IEEE754**：单/双精度 HEX ↔ 浮点
10. **收藏/历史**：只存用户主动收藏的条目（见坑 #11）

### 明确不做（避免膨胀）
- 十进制**裸数字**的 regex 匹配指令（会匹配手机号、端口、金额、行号，污染整个搜索面板）
- 表达式求值（`1<<12`、`0x0F & 0x30`）—— 那是计算器插件
- 颜色、ASCII/Unicode、时间戳、Base64/URL、大小写转换

## 四、plugin.json 指令设计（草案）

```json
{
  "main": "index.html",
  "logo": "logo.png",
  "pluginSetting": { "single": true, "height": 420 },
  "features": [
    {
      "code": "convert",
      "explain": "进制转换（2/8/10/16 互转）",
      "cmds": ["进制转换", "进制", "base"]
    },
    {
      "code": "hex",
      "explain": "十六进制字面量 → 十进制/二进制/八进制",
      "cmds": [{
        "type": "regex",
        "label": "十六进制转换",
        "match": "/^0[xX][0-9a-fA-F][0-9a-fA-F_\\s]*$/",
        "minLength": 3,
        "maxLength": 200
      }]
    },
    {
      "code": "bin",
      "explain": "二进制字面量 → 十进制/十六进制/八进制",
      "cmds": [{
        "type": "regex",
        "label": "二进制转换",
        "match": "/^0[bB][01][01_\\s]*$/",
        "minLength": 3,
        "maxLength": 200
      }]
    },
    {
      "code": "oct",
      "explain": "八进制字面量 → 十进制/十六进制/二进制",
      "cmds": [{
        "type": "regex",
        "label": "八进制转换",
        "match": "/^0[oO][0-7][0-7_\\s]*$/",
        "minLength": 3,
        "maxLength": 200
      }]
    }
  ]
}
```

要点：
- **中文功能指令自动支持拼音/首字母**，不用额外配。
- 正则里所有 `\` 必须写成 `\\`（JSON 转义）；**不要用 `/.*/` 之类的任意匹配正则，会被 uTools 直接忽略**。
- 匹配指令 `label` 刻意与功能指令名区分，避免候选列表里出现两个一样的名字。
- 三个匹配指令进入插件时都走同一个 `convert` 界面（payload 是字符串，预填输入框），不做三套 UI。
- 是否加 `mainPush`：**暂不加**。`onMainPush` 能把结果推到主搜索框候选里，但它对所有输入都会触发（含裸数字），先跑通 regex 再看要不要。

## 五、界面与交互设计

### 布局（单页，无路由切换）

```
┌────────────────────────────────────────────┐
│ [ 0x7FFFFFFF            ]  ← 输入框（自动识别）│  顶部：当前识别进制标签 filled 圆角
├────────────────────────────────────────────┤
│ DEC   2147483647                    [复制] │
│ HEX   7FFFFFFF                      [复制] │
│ BIN   0111 1111 1111 ... 1111       [复制] │
│ OCT   17777777777                   [复制] │
├────────────────────────────────────────────┤
│ 32位  ○ 无符号 4294967295  ● 有符号 -1      │  v1.5：位宽/符号
│ 字节序  12 34 56 78  |  78 56 34 12        │  v1.5
│ IEEE754  0x3F800000 = 1.0f                 │  v1.5
│ 位图    1111 1111 ... （点阵）              │  v1.5
└────────────────────────────────────────────┘
```

### 交互原则（对应你既有的偏好）

- **实时联动，但动作显式**：进制之间是纯映射、无副作用，输入即出结果比"点计算"更顺；而**复制 / 粘贴回原窗口 / 收藏**这类有副作用的动作，一律显式按钮或回车触发，不做自动触发。
- **点击数字即复制**（不用选中），复制后插件内轻提示（`utools.showNotification` 是系统通知，太吵，不用它做每次复制的反馈）。
- **键盘优先**：`↑/↓` 在行间移动、`Enter` 复制当前行、`Esc` 退出、`Cmd+数字` 直接切到某进制。
- **输入框服务你的 UI 偏好**：聚焦边框 `#409eff`、默认边框 `#d9d9d9`、圆角 `6px`；状态标签用 filled 圆角矩形白字。
- **高度自适应**：内容变化时 `utools.setExpendHeight()`，默认约 420（比 uTools 默认 544 矮，不占屏幕）。
- **配色跟随系统深浅色**（uTools 插件运行在 Electron 里，用 `prefers-color-scheme` + CSS 变量，不要写死背景）。
- 匹配指令进入时（payload 有值）自动聚焦结果、把输入框置于 "回编辑" 状态。

## 六、技术方案与关键算法

### 6.1 解析与输出

```js
// 统一入口：把用户输入归一化成 { ok, radix, value: BigInt } 或 { ok:false, message }
// 1) 全角 → 半角（中文输入法下会输入 ０ｘ１Ｆ）
// 2) 去掉空格 / 下划线 / 逗号分隔符
// 3) 识别前缀 0x/0b/0o，无前缀默认按 10 进制
// 4) BigInt(str) 直接接受 "0x1f" / "0b1010" / "0o17" 字面量
// 5) 输出用 value.toString(2|8|10|16)，进制上限 36
```

- **BigInt 是必须的**：`Number` 超过 2^53 就丢精度，而 64 位寄存器值（`0xFFFFFFFFFFFFFFFF`）是日常。
- 前导 `+/-` 单独处理（BigInt 不接受 `+`，`-` 可以）。

### 6.2 位宽与补码（最容易做错，也是嵌入式最需要）

```js
BigInt.asUintN(32, -1n)  // 4294967295n  —— 32 位无符号
BigInt.asIntN(32, 0xFFFFFFFFn) // -1n   —— 32 位有符号
BigInt.asUintN(8, 0x1FFn) // 255n       —— 截断
```

这两个 API 就是为"寄存器按宽度解释"存在的，不要手写补码逻辑。
注意：`(-1n).toString(2)` 得到的是 `"-1"`，**不是** `11111111...`，补码必须经过 `asUintN` 再 `toString(2)`。

### 6.3 分组补零显示

```js
const padBin = (v, width) => v.toString(2).padStart(width, '0').replace(/(.{4})(?=.)/g, '$1 ');
// 0x0F → "0000 1111"；十六进制同理按 2 位分组
```

### 6.4 字节序

```js
// BigInt → 字节数组（大端）；小端即 reverse
const toBytes = (v, width) => Array.from({length: width / 8},
  (_, i) => Number((v >> BigInt(8 * (width / 8 - 1 - i))) & 0xFFn).toString(16).padStart(2, '0'));
// 0x12345678, 32 → ["12","34","56","78"]，小端 "78 56 34 12"
```

### 6.5 IEEE754

用 `DataView` 实现，不要手算位域：

```js
const buf = new ArrayBuffer(4); const dv = new DataView(buf);
dv.setUint32(0, 0x3F800000); dv.getFloat32(0); // 1
// 双精度用 8 字节 setBigUint64/getFloat64
```

### 6.6 测试

转换逻辑全部抽成**无副作用纯函数**放在 `src/utils/base.js`，用 Vitest 单测（与 UI 完全解耦）。UI 只负责取值和展示。

## 八、坑清单（已核实）

| # | 坑 | 应对 |
|---|---|---|
| 1 | plugin.json 正则里 `\` 要写 `\\`；任意匹配正则被忽略 | 见第四节写法 |
| 2 | `payload` 结构按 type 不同：`regex`/`over` → **字符串**；`files` → 对象数组（`payload[0].path`）；`img` → base64 data URL | 按 type 分支处理，模板 `Read/index.vue` 就是现成参照 |
| 3 | `(-1n).toString(2)` 不是补码 | 用 `BigInt.asUintN` |
| 4 | 全角数字/字母（中文输入法）| 输入先做全角→半角归一化 |
| 5 | 十进制裸数字做 regex 会污染搜索面板 | 不做 |
| 6 | 开发时改了代码不生效 | 开发者工具里开「退出到后台立即结束运行」 |
| 7 | `development.main` 白屏 | 项目现在写的是 `http://localhost:5173`；白屏就换成 `http://127.0.0.1:5173/index.html` |
| 8 | 打包范围错 | 只打包 `dist` + `plugin.json` + `logo`，**绝不打包项目根目录** |
| 9 | 界面高度写死 | `setExpendHeight` 随内容自适应 |
| 10 | `utools.showNotification` 每次复制都弹系统通知 | 插件内自绘轻提示 |
| 11 | **同步 DB 红线**：高频/临时数据（输入历史、日志）写同步 DB 会被下架 | 历史只存"用户主动收藏"的条目；不记录每次输入 |
| 12 | 无 preload 的 `single` 行为 | `pluginSetting.single: true`（默认）即可，转换场景无需多开 |
